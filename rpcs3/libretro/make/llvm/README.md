# LLVM for the Makefile build

The Makefile builds the LLVM the core links from the sources in
`3rdparty/llvm/llvm` with make and a compiler, without CMake. Those sources
are part of this repository: the files of LLVM 22.1.8 (llvm-project
ca7933e47d) that the lists here name, with the headers and TableGen inputs
they need, and nothing else of LLVM - no CMake, tests, tools or other
targets. They are the core's own to change. The CMake build's `BUILD_LLVM`
has this Makefile build them too (`make llvm`), so every build that builds
LLVM builds the same one. What it needs to know,
and LLVM's CMake would otherwise work out, is here:

- `llvm.mk`: the sources of each library the core's components need (the
  common ones, X86, AArch64, the perf JIT listener), the include directories
  and defines each is compiled with, the sources of `llvm-min-tblgen` and
  `llvm-tblgen`, and every TableGen run, with its arguments.
- `include/`: the headers LLVM's configuration writes. `config.h` and
  `llvm-config.h` for each system (`linux`, `windows`, `darwin`), the
  target lists for each target (`x86`, `aarch64`), and the rest (`common`).

Both were generated by `gen.py` from LLVM's own build description, which
needs LLVM's whole source with its CMake: a checkout of llvm-project beside
the repository, not the trimmed copy in it. To move to another LLVM,
configure that checkout twice with CMake and Ninja, for Linux and for MinGW,
run the script, and copy the files the new lists name into
`3rdparty/llvm/llvm` (with `S` the checkout's `llvm` directory):

    S=../llvm-project/llvm
    OPTS="-DCMAKE_BUILD_TYPE=Release -DLLVM_TARGETS_TO_BUILD=X86;AArch64 \
      -DLLVM_ENABLE_ZLIB=OFF -DLLVM_ENABLE_ZSTD=OFF -DLLVM_ENABLE_LIBXML2=OFF \
      -DLLVM_ENABLE_TERMINFO=OFF -DLLVM_ENABLE_LIBEDIT=OFF -DLLVM_ENABLE_LIBPFM=OFF \
      -DLLVM_INCLUDE_TESTS=OFF -DLLVM_INCLUDE_BENCHMARKS=OFF -DLLVM_INCLUDE_EXAMPLES=OFF \
      -DLLVM_INCLUDE_DOCS=OFF -DLLVM_BUILD_TOOLS=OFF -DLLVM_ENABLE_BINDINGS=OFF \
      -DLLVM_USE_INTEL_JITEVENTS=OFF -DLLVM_USE_PERF=ON -DLLVM_DISABLE_ASSEMBLY_FILES=ON"
    cmake -G Ninja -S $S -B /tmp/llvm-linux $OPTS
    cmake -G Ninja -S $S -B /tmp/llvm-mingw $OPTS -DCMAKE_TOOLCHAIN_FILE=mingw.cmake \
      -DLLVM_TABLEGEN=/tmp/llvm-linux/bin/llvm-tblgen -DLLVM_HOST_TRIPLE=x86_64-w64-windows-gnu
    python3 rpcs3/libretro/make/llvm/gen.py /tmp/llvm-linux /tmp/llvm-mingw

(`mingw.cmake` names x86_64-w64-mingw32-gcc-posix and -g++-posix as the C and
C++ compilers, for CMAKE_SYSTEM_NAME Windows.) The script needs Ninja for
`ninja -t commands`; nothing is built. macOS has no configuration of its
own here: `gen.py` writes its `config.h` from Linux's, with what Darwin has
and lacks.

Left out, as LLVM's CMake would leave them out with these options: Intel's
VTune JIT listener (its ittapi sources are downloaded by LLVM's CMake, not
part of LLVM) and BLAKE3's assembly (the portable C is used).
